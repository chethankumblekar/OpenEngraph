## Where OpenEngraph is ahead

> ⚠️ **Strategic flag — re-read before quoting the uniqueness claim externally.** As of this run, OpenEngraph is no longer the *only* OSS, fully-local, hybrid (graph + embeddings) tool: `codebase-memory-mcp` shipped a local bundled-embeddings layer this cycle, and a brand-new, very early-stage project (`LocalNest MCP`) also claims local hybrid BM25+vector retrieval plus a temporal knowledge graph. See the Change Log entry below for sources. The claim still holds cleanly against every *commercial* competitor (Augment, Cody, Cursor, Unblocked all still send the embeddings step to the cloud), so the positioning doc's core argument is not wrong, just narrower than "every sampled competitor" — it should say "every commercial competitor and most OSS peers" rather than "every entrant."

- Against the **commercial** tier: still the only entrant that is simultaneously open-source, fully local (including the embedding step), and hybrid. Every commercial hybrid player (Augment, Cody, Cursor, Unblocked) remains closed-source and cloud-dependent for the embedding half.
- Against the **OSS/local** tier: no longer unique on hybrid retrieval alone (see flag above), but still has a graph-first *query router* — structural questions resolve deterministically via the graph before falling back to embeddings — rather than a flat fusion of signals. Whether that's a materially better retrieval architecture than peers' approaches is a product question this research run can't settle; flagging for a human call rather than asserting an advantage the research doesn't support.
- Cheapest possible trust story for security-conscious/regulated users remains true in absolute terms (no subscription, no code leaving the machine), but it's now shared by at least two-three OSS peers rather than unique to OpenEngraph.

## Where OpenEngraph is behind (by design — enterprise-roadmap scope)

- No multi-repo/org-wide graph (Augment, Cody, Port/Cortex/Backstage all have this; `codebase-memory-mcp` now has a partial/opt-in version too).
- No cross-system connectors (Unblocked remains the clear commercial leader: GitHub/GitLab/Bitbucket/Slack/Jira/Confluence/Notion/Google Drive).
- No temporal/commit-lineage intelligence (Augment's "Context Lineage" is the direct commercial analog) — **and now also behind two OSS peers on some version of this**: `codebase-memory-mcp`'s git-diff impact mapping and `LocalNest MCP`'s time-travel knowledge graph. Neither is full commit-lineage history, but both narrow the "this is purely enterprise-roadmap, no rush" framing for this specific item.
- No infrastructure intelligence (Cortex/Port/Backstage's whole reason to exist; `codebase-memory-mcp` now has a partial K8s/Docker-Compose version).
- Narrower language coverage than most OSS peers — codebase-memory-mcp (162), Graphify (~40), CodeGraph (34) all exceed OpenEngraph's 3 (TypeScript/Python/Go). This remains the most actionable near-term gap: it's OSS-Phase-1 scope, not enterprise-roadmap scope, and existing plugins already establish the pattern for adding a language.

## Notes on open-source local-first peers specifically

`CodeGraph`, `codebase-memory-mcp`, `Graphify`, and `LocalNest MCP` are the peers OpenEngraph should track most closely — same tier, same target user. As of this run:
- `codebase-memory-mcp` **has added a real local embeddings layer** (bundled `nomic-embed-code`, int8, compiled into the binary, no API key) plus cross-repo linking, K8s/Docker infra mapping, and git-diff impact analysis — it has materially closed several of the gaps this matrix lists as OpenEngraph's enterprise-roadmap scope, all for free and OSS. This is the single most consequential finding of this run and the one most worth a human strategic read: a free, MIT-licensed peer now covers hybrid retrieval *and* partial multi-repo *and* partial infra-intelligence *and* partial temporal intelligence. Source: `github.com/DeusData/codebase-memory-mcp` README, read directly.
- `CodeGraph` remains structural-only — direct confirmation this run that its "Semantic Code Intelligence" tagline is marketing copy for the structural graph, not an embeddings layer. Its true language count is 34 (counted directly from its own README's language list this run, resolving prior "20+ vs. 34+ disputed" uncertainty), and it now includes Terraform/OpenTofu as a parsed language (not infra-graph linking).
- `Graphify` (new this run) is a YC S26 company's OSS skill/CLI, dual-licensed Apache-2.0/MIT, with far larger adoption than any other OSS peer tracked here — **128.5k GitHub stars, confirmed directly from `github.com/Graphify-Labs/graphify`'s own repo page this run** (prior estimate of "tens of thousands, 80k-97k" from third-party aggregators was stale/understated; the repo's own README also independently confirms the YC S26 badge, the dual license, and "no embeddings, no vector store" for the code-graph path). Its code-graph path is deterministic/local like CodeGraph's (no embeddings), but it also does an LLM-based semantic enrichment pass over docs, PDFs, and other media, and supports SQL/Postgres/Terraform ingestion as optional extras, plus an optional paid "Graphify Cloud" always-on layer.
- `LocalNest MCP` (new this run, `wmt-mobile/localnest`, npm `localnest-mcp`) is real but extremely early-stage (single-digit GitHub stars at time of check) — it claims local hybrid BM25+vector search and a temporal knowledge graph with time-travel queries, confirmed directly from its README, but low adoption means it's worth re-checking for traction rather than treating as an established threat yet.

`codebase-memory-mcp`'s community fork `win4r/codebase-memory-mcp-pro` (MIT, tracks upstream) states its first integrated fix is the same class of bug as [issue #3](https://github.com/chethankumblekar/OpenEngraph/issues/3) fixed in this repo (incremental-reindex correctness for cross-file CALLS edges, tracked upstream as issue #528) — it ships no prebuilt binaries, build-from-source only. Source: `github.com/win4r/codebase-memory-mcp-pro` README (via search; not read directly from raw source this run).
